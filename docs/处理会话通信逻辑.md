## 发送一条消息后，后端接收和返回的完整信息流

### 1. 前端发起：`CodexBackend.startTurn()`

当用户发送一条消息时，`Index.ets` 调用 `codexBackend.startTurn(request)`，构建的请求对象是 `CodexTurnRequest`：

```
CodexTurnRequest {
  threadKey,           // 本地会话标识
  title,               // 会话标题
  workspaceId,         // 工作区 ID
  workspaceRoot,       // 工作区路径（cwd）
  workspacePermissionState,  // 权限状态: writable/readonly/unavailable/revoked
  workspaceAccessKind,       // 访问类型: sandbox/user_granted/readonly/unknown
  writableRoots,       // 可写目录列表
  model,               // 模型名称（如 "default" 则不传）
  reasoningEffort,     // 推理强度（如 "default" 则不传）
  prompt               // 用户输入的文本
}
```

### 2. 会话创建/恢复（自动处理）

`startTurn` 首先通过 `ensureRemoteThread()` 确保远程会话存在：

**新建会话 → `thread/start`**
- 请求：`{ cwd, model }`
- Rust 层转换为 `ThreadStartParams`，补充 `approval_policy: "on-request"`, `approvals_reviewer: User`, `sandbox: "workspace-write"`, `model_provider: "harmony-openai-compatible"`, `ephemeral: false`, `persist_extended_history: true`
- 返回：`{ thread: { id }, model, cwd, error? }`

**恢复会话 → `thread/resume`**
- 请求：`{ threadId, cwd, model }`
- 同样补充上述参数
- 返回：`{ thread: { id }, error? }`

### 3. 发送 Turn：`turn/start`

请求（`TurnStartRequestPayload`）：
```json
{
  "threadId": "...",
  "input": [{ "type": "text", "text": "用户消息内容" }],
  "cwd": "/path/to/workspace",
  "model": "gpt-5.4",          // 可选
  "effort": "medium",           // 可选，reasoning effort
  "approvalPolicy": "on-request", // Rust 层自动填充
  "sandboxMode": "workspace-write" // Rust 层自动填充
}
```

Rust 层实际发送给 codex app-server 的 `TurnStartParams`：
```
thread_id, cwd, model, effort, model_provider("harmony-openai-compatible"),
approval_policy(AskForApproval::OnRequest), approvals_reviewer(User),
sandbox_policy, input(Vec<UserInput::Text>),
persist_extended_history(true), ephemeral(false)
```

**`turn/start` 返回：**
```json
{
  "turn": {
    "id": "turn_xxx",
    "status": "inProgress"   // 或 "failed"
  }
}
// 失败时:
{
  "turn": { "id": "", "status": "failed", "error": { "message": "..." } }
}
```

### 4. 轮询 Turn 状态：`turn/poll`（每 800ms）

前端进入轮询循环 `pollTurnUntilCompleted()`，每次调用 `turnPollNative(threadId, turnId)`。

Rust 层收到 `turn/poll` 后做三件事：
1. **`process_pending_events`** — 从 app-server websocket 消费所有待处理事件
2. **等待尾随 diff**（如果 turn 已结束但 diff 为空，额外等待 300ms）
3. **从本地 diff tracker 刷新**（如果有文件系统变更但服务端没推 diff）

**`turn/poll` 返回的 payload（`build_turn_poll_payload`）：**
```json
{
  "threadId": "...",
  "turnId": "...",
  "status": "inProgress | completed | failed | interrupted",
  "messages": [
    { "messageId": "turnId:itemId", "author": "Codex", "role": "assistant", "content": "...", "timestamp": "..." }
  ],
  "summaryTitle": "执行中 | 计划中 | 推理中 | 本轮已完成 | 本轮失败",
  "summary": ["计划: ...", "推理摘要: ...", "命令输出: ..."],
  "diff": "unified diff 文本"
}
```

### 5. 后端推送的事件类型（通过 WebSocket `ServerNotification`）

Rust 层通过 `apply_server_notification()` 处理以下事件，并更新内部 turn 状态：

| 事件                          | summaryTitle                             | summary 内容                                  | 其他更新                                                                        |
| ----------------------------- | ---------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------- |
| `TurnStarted`                 | "执行中"                                 | "Codex 正在处理请求"                          | 设置 turn cwd、创建 diff tracker                                                |
| `ItemStarted`                 | "执行中"                                 | 描述 item 类型（命令/文件变更/MCP工具等）     | status → inProgress                                                             |
| `AgentMessageDelta`           | "执行中"                                 | "Codex 正在生成回复"                          | **流式追加** assistant message delta                                            |
| `PlanDelta`                   | "计划中"                                 | "计划: {delta 文本截断160字}"                 | —                                                                               |
| `ReasoningSummaryTextDelta`   | "推理中"                                 | "推理摘要: {delta 截断160字}"                 | —                                                                               |
| `ReasoningTextDelta`          | "推理中"                                 | "推理: {delta 截断160字}"                     | —                                                                               |
| `CommandExecutionOutputDelta` | "执行工具中"                             | "命令输出: {delta 截断160字}"                 | —                                                                               |
| `FileChangeOutputDelta`       | "更改文件中"                             | "文件变更: {delta 截断160字}"                 | —                                                                               |
| `McpToolCallProgress`         | "执行工具中"                             | "工具进度: {message 截断160字}"               | —                                                                               |
| `ItemCompleted`               | —                                        | 描述完成状态（计划/推理/命令/文件/MCP工具等） | **同步完整 message**、**追加 diff**（来自 FileChange）、diff_authoritative=true |
| `TurnCompleted`               | "本轮已完成" / "本轮失败" / "本轮已结束" | "本轮对话已完成" 或 error.message             | status 终态、设置 error_message                                                 |
| `TurnDiffUpdated`             | —                                        | —                                             | 更新 diff 文本、diff_authoritative=true                                         |
| `Error`                       | "本轮失败"                               | error.message                                 | status → failed                                                                 |

**ItemCompleted 中各类型的摘要描述：**

| ThreadItem 类型       | 完成时 summary                                 |
| --------------------- | ---------------------------------------------- |
| `Plan`                | "计划已生成: {text截断160}"                    |
| `Reasoning`           | "推理完成: {summary或content截断160}"          |
| `CommandExecution`    | "命令已完成/失败: {command截断120} (exit=code) |
| `FileChange`          | "文件变更已完成/失败，共 N 处"                 |
| `McpToolCall`         | "MCP 工具 server/tool 已完成/失败: error?"     |
| `DynamicToolCall`     | "动态工具 tool 已完成/失败"                    |
| `CollabAgentToolCall` | "协作工具 {:?} 已完成/失败"                    |
| `WebSearch`           | "网络搜索完成: {query截断120}"                 |
| `ImageView`           | "图像已加载: path"                             |
| `ImageGeneration`     | "图像生成状态: status                          |
| `ContextCompaction`   | "上下文压缩已完成"                             |

### 6. 审批请求（Approval）

当 codex 需要用户批准操作时，Rust 层收到 `ServerRequest`，存入 `pending_approval`。前端每 1000ms 轮询 `approval/poll`。

**5 种审批类型：**

| 类型                              | kind          | title                         | detail 包含                              |
| --------------------------------- | ------------- | ----------------------------- | ---------------------------------------- |
| `CommandExecutionRequestApproval` | "command"     | "需要批准执行命令: {command}" | reason, cwd, command, availableDecisions |
| `FileChangeRequestApproval`       | "fileChange"  | "需要批准文件修改"            | reason, grantRoot                        |
| `PermissionsRequestApproval`      | "permissions" | "需要批准权限申请"            | reason, permissions                      |
| `ApplyPatchApproval`              | "fileChange"  | "需要批准补丁修改"            | reason, grantRoot, fileChanges           |
| `ExecCommandApproval`             | "command"     | "需要批准执行命令"            | reason, cwd, command                     |

前端调用 `approvePendingRequest()` 或 `declinePendingRequest()` 后，Rust 层根据 `resolution_kind` 构造对应的 approval response 发回 app-server。

### 7. Turn 结束后的恢复

如果 turn 结束后 diff 为空或统计为 `+0 -0`，前端会额外执行：
1. **drainLateTurnUpdates** — 最多 3 次额外 poll（间隔 250ms）
2. **recoverDiffFromThreadHistory** — 调用 `thread/read` 恢复完整 diff（最多 3 次，间隔 250ms）

`thread/read` 返回的完整 payload：
```json
{
  "thread": { "id", "title", "name", "preview", "cwd", "createdAt", "updatedAt", "path", "modelProvider", "ephemeral", "status", "statusText" },
  "messages": [{ "messageId", "author", "role", "content", "timestamp" }],
  "summaryTitle": "...",
  "summary": ["..."],
  "changedFiles": ["file1.ts", "file2.ets"],
  "changedFilesText": "file1.ts、file2.ets",
  "diff": "unified diff 文本",
  "diffStat": "+N -M",
  "lastTurnId": "...",
  "lastTurnStatus": "completed | failed | interrupted | inProgress"
}
```

### 完整流程图

```
用户输入 "帮我写一个函数"
  │
  ▼
CodexBackend.startTurn(CodexTurnRequest)
  │
  ├─ ensureRemoteThread()
  │   ├─ 新会话: thread/start → { thread: {id}, model, cwd }
  │   └─ 恢复: thread/resume → { thread: {id} }
  │
  ├─ beginLocalTurn() → 本地先插入 user message
  │
  ├─ turn/start → { turn: {id, status} }
  │   Rust 层发送给 app-server:
  │   TurnStartParams { thread_id, input: [UserInput::Text{text}], cwd, model,
  │                     effort, approval_policy, approvals_reviewer, sandbox_policy,
  │                     model_provider, ephemeral, persist_extended_history }
  │
  └─ pollTurnUntilCompleted() 循环:
      │
      ├─ turn/poll (每 800ms)
      │   Rust 层消费 WebSocket 事件:
      │   ├─ TurnStarted      → 初始化 turn state
      │   ├─ ItemStarted      → 更新 summaryTitle + summary
      │   ├─ AgentMessageDelta → 流式追加 assistant message
      │   ├─ PlanDelta        → 更新 summaryTitle="计划中"
      │   ├─ ReasoningSummaryTextDelta → summaryTitle="推理中"
      │   ├─ ReasoningTextDelta       → summaryTitle="推理中"
      │   ├─ CommandExecutionOutputDelta → summaryTitle="执行工具中"
      │   ├─ FileChangeOutputDelta     → summaryTitle="更改文件中"
      │   ├─ McpToolCallProgress       → summaryTitle="执行工具中"
      │   ├─ ItemCompleted  → 同步完整 message + 追加 diff
      │   ├─ TurnDiffUpdated → 更新 diff
      │   ├─ TurnCompleted  → 设置终态 status
      │   └─ Error          → status=failed
      │
      │   返回给前端:
      │   { threadId, turnId, status, messages[], summaryTitle, summary[], diff }
      │
      ├─ 同时并行: approval/poll (每 1000ms)
      │   检查 pending_approval → 展示审批卡片
      │   用户批准/拒绝 → approval/approve 或 approval/decline
      │
      └─ status != "inProgress" → 轮询结束
          │
          ├─ drainLateTurnUpdates (最多3次, 250ms间隔)
          └─ recoverDiffFromThreadHistory (如果diff仍为空, 调用thread/read恢复)
              → 最终返回 CodexTurnResult
```

### 前端最终拿到的 `CodexTurnResult`

```typescript
CodexTurnResult {
  threadId: string;         // 远程会话 ID
  turnId: string;           // 本轮 ID
  status: 'completed' | 'failed' | 'inProgress' | 'interrupted';
  messages: CodexChatMessage[];  // 完整对话消息列表
  diffLines: CodexDiffLine[];    // 解析后的 diff 行
  summaryTitle: string;          // 摘要标题
  summaryPoints: string[];       // 摘要要点列表
  changedFiles: string;          // 变更文件列表（逗号分隔）
  diffStat: string;              // diff 统计 "+N -M"
}
```

其中每条 `CodexChatMessage` 包含 `messageId, sequence, author, role, content, timestamp`，每条 `CodexDiffLine` 包含 `lineId, sequence, lineNumber, sign(+/-/ ), content, kind(add/delete/context)`。
