# 聊天消息展示中间步骤改进

日期：2026-05-05（更新）

## 1. 问题现象

之前聊天界面只显示 Codex 的最终回答（AgentMessage），而思考过程（Reasoning）、工具调用（McpToolCall）、命令执行（CommandExecution）等中间步骤只出现在侧边 summary 区域的短文本中，不在聊天消息流中展示。

用户希望像官方 Codex CLI/TUI 一样，在聊天中展示完整的中间步骤。

## 2. 数据流分析

### 修改前的数据流

```
WebSocket Event (ServerNotification)
  ↓
Rust 后端 apply_server_notification()
  ↓
只有 AgentMessageDelta/AgentMessage 会生成 NativeMessage
其他事件只更新 summary 数组
  ↓
turn/poll 返回 messages + summary
  ↓
前端只拿到 AgentMessage，其他信息在 summary 中
```

### 官方 Codex TUI 的做法

- 每种 `ThreadItem` 类型都有对应的 `HistoryCell` 实现
- 不同类型用不同的视觉样式区分（颜色、前缀、图标）
- 工具调用、命令执行等都在主视图中显示

## 3. 修改方案

### 3.1 Rust 后端（ohos-host/src/lib.rs）

**扩展 NativeMessage 结构：**

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
#[serde(rename_all = "camelCase")]
struct NativeMessage {
    message_id: String,
    author: String,
    role: String,
    content: String,
    timestamp: String,
    item_type: Option<String>,      // 新增
    status: Option<String>,          // 新增
    metadata: Option<serde_json::Value>,  // 新增
}
```

**修改事件处理逻辑：**

- `ItemStarted` 事件：调用 `upsert_item_started_message()` 创建初始消息（状态 `inProgress`）
- `ItemCompleted` 事件：调用 `upsert_item_completed_message()` 更新为最终状态消息
- `collect_thread_messages()`：历史消息加载时也包含所有类型的消息

**新增辅助函数：**

- `thread_item_to_message()` - 将已完成的 ThreadItem 转换为消息
- `thread_item_started_to_message()` - 将开始中的 ThreadItem 转换为消息
- `thread_item_id()` - 提取 ThreadItem 的 ID
- `upsert_item_started_message()` - 创建/更新进行中状态的消息
- `upsert_item_completed_message()` - 创建/更新完成状态的消息

**支持的消息类型：**

| itemType | author | role | 来源 ThreadItem |
|----------|--------|------|-----------------|
| plan | 计划 | plan | Plan |
| reasoning | 思考过程 | reasoning | Reasoning |
| command | 命令执行 | command | CommandExecution |
| file | 文件变更 | file | FileChange |
| tool | MCP 工具 | tool | McpToolCall |
| tool | 动态工具 | tool | DynamicToolCall |
| tool | 协作工具 | tool | CollabAgentToolCall |
| search | 网络搜索 | search | WebSearch |
| image | 图像生成 | image | ImageGeneration |
| image | 图像查看 | image | ImageView |
| hook | Hook提示 | hook | HookPrompt |
| review | 审查模式 | review | EnteredReviewMode, ExitedReviewMode |
| system | 上下文压缩 | system | ContextCompaction |
| agent | Codex | assistant | AgentMessage |
| — | 用户 | user | UserMessage |

### 3.2 前端业务逻辑（CodexBackend.ets）

**扩展消息角色类型：**

```typescript
export type CodexMessageRole = 'user' | 'assistant' | 'system' | 'reasoning' | 'command' | 'tool' | 'file' | 'search' | 'plan' | 'image' | 'hook' | 'review';
```

**扩展 CodexChatMessage 类：**

```typescript
export class CodexChatMessage {
  // ... 原有字段
  itemType?: string;
  status?: string;
  metadata?: Record<string, Object>;
}
```

**修改的方法：**

- `applyTurnPollResult()` - 解析 itemType、status、metadata
- `messagesFromPayload()` - 解析 itemType、status、metadata
- `mergeThreadMessages()` - 保留新字段
- `cloneMessage()` - 保留新字段
- 新增 `mapMessageRole()` - 将后端角色映射为前端角色类型

### 3.3 前端 UI（Index.ets）

**扩展 ChatMessage 类：**

```typescript
class ChatMessage {
  // ... 原有字段
  itemType?: string;
  status?: string;
  metadata?: Record<string, Object>;
}
```

**修改 messageCard() 渲染：**

- 不同类型显示不同图标（🧠⚡🔧📄🔍📋🖼️🪝👁️⚙️）
- 进行中/失败状态显示标签指示器
- 不同类型使用不同的背景色、边框色、文字颜色

**新增辅助方法：**

- `messageIcon()` - 根据类型返回图标
- `statusLabel()` - 将状态码转为中文标签
- `statusColor()` / `statusBgColor()` - 状态颜色
- `messageContentColor()` - 内容文字颜色

## 6. 测试验证

可以通过以下场景验证：

1. 发送 "帮我分析这段代码" → 应看到 reasoning 消息（黄色，🧠图标）
2. 发送 "列出当前目录文件" → 应看到 command execution 消息（绿色，⚡图标）
3. 使用 MCP 工具 → 应看到 tool call 消息（蓝色，🔧图标）
4. 请求修改文件 → 应看到 file change 消息（紫色，📄图标）
5. 进行网络搜索 → 应看到 search 消息（绿色，🔍图标）
6. 调用创建子代理工具 → 应看到协作工具消息（蓝色，🔧图标）
7. Hook 触发 → 应看到 Hook 提示消息（琥珀色，🪝图标）
8. 进入审查模式 → 应看到审查模式消息（黄色，👁️图标）
9. 上下文压缩触发 → 应看到系统消息（灰色，⚙️图标）

## 7. 后续优化建议

1. **消息折叠**：对于推理过程、命令输出等可能较长的内容，可以添加折叠/展开功能
2. **实时更新**：对于进行中的任务，可以添加动画效果
3. **元数据展示**：对于工具调用，可以展示完整的参数和返回值
4. **过滤功能**：添加消息类型过滤，用户可以选择只显示特定类型
