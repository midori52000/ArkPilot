# 验收计划

## 1. 目标

把当前已完成的 ArkPilot 上下文管理能力按真实场景走一遍，确认：

- 主工作台能稳定展示 `contextManagement`
- 微压缩 / memory / full compaction / auto-compact 的状态能看懂
- 重启后能恢复主要状态
- 不会把未实现项当成已完成项

---

## 2. 本次验收范围

### 2.1 验收什么

1. `contextManagement` 的展示与恢复
2. Layer 1 微压缩
   - `ToolSearchOutput`
   - `LocalShellCall` 配对 output
   - 大 JSON / API 返回 output
   - `WebSearchCall`
   - `apply_patch` / diff-write 类 output
3. memory 相关状态
   - `memoryMode`
   - summary / preview / 更新时间
   - polluted / forgetting
   - phase2 / stage1 usage / stage1 job
4. full compaction 只读观测
   - trigger
   - provider mode
   - trimmed item count
   - reference context reestablished
   - recent artifact refs
5. auto-compact 的失败计数、熔断状态、ArkTS fallback 边界
6. 重启后 `thread/read` / `turn/poll` 的状态恢复

### 2.2 不验收 / 待后续

以下内容不作为本次通过条件：

- `auto-compact cooldown`
- `skip reason`
- memory 编辑器
- artifact 诊断页
- 独立 context 设置页
- 新的 host / ArkTS 状态字段
- 第二套调度器或解释逻辑

---

## 3. 你怎么执行

每个场景都按这个顺序：

1. 复制“发给 ArkPilot 的指令”
2. 在 ArkPilot 中发送
3. 看指定 UI 区域
4. 把结果按模板发给我

你主要看：

- token/context 卡片
- Memory 行
- 微压缩摘要
- 完整压缩 notice
- recent artifact refs
- 熔断器 / fallback 提示

---

## 4. 验收前准备

1. 应用能在设备或模拟器上启动
2. 你能进入主工作台
3. 你能打开一个已有线程，或新建一个线程
4. 你能正常发一轮基础对话
5. 最好准备一个**新线程**和一个**长线程**

---

## 5. 场景 1：基础展示与线程恢复

### 发给 ArkPilot 的指令

如果是已有线程，直接发：

```text
继续刚才的任务，不要切换目标，先基于当前线程的已有上下文给我一句话说明你现在正在做什么。
```

切到别的线程再切回来后，再发：

```text
继续当前线程的任务，再用一句话说明你现在基于的上下文是什么。
```

重启应用并重新进入该线程后，再发：

```text
继续刚才的任务，如果你还记得当前线程上下文，就直接往下做，不要重新开始。
```

### 你看什么

- 主卡片里的 `contextManagement` 是否出现
- 切线程后是否跟着变
- 重启后是否还能恢复
- 有没有明显串线程

### 你发给我什么

- 哪些摘要还在
- 切线程后有没有异常
- 重启后有没有异常
- 是否有明显旧线程状态残留

### 通过标准

- 主卡片稳定显示摘要
- 切线程会跟着切
- 重启后能恢复
- 不串线程

## 6. 场景 2：微压缩

### 发给 ArkPilot 的指令

#### 2.1 触发 shell / command output

```text
请在当前工作区执行 git status，然后完整输出结果，不要总结。
```

```text
请在当前工作区执行 git diff --stat，然后完整输出结果，不要省略。
```

#### 2.2 触发工具搜索结果

```text
请在当前工作区搜索所有和 contextManagement、compaction、memory 相关的代码位置，把匹配结果尽量完整列出来，不要只给结论。
```

#### 2.3 触发大 JSON / API 风格输出

```text
请尽量调用一个会返回结构化长结果的工具，并把原始结果完整展示给我，不要改写成摘要。
```

#### 2.4 触发 diff / write 结果

```text
请在仓库里创建一个临时文本文件，内容只写一行 hello，再把工具返回结果完整告诉我。
```

#### 2.5 继续压长线程

```text
继续当前线程的任务，如果刚才已经产生了较长工具输出，就继续往下做，不要重置上下文。
```

### 你看什么

- 微压缩摘要有没有变化
- 最近一次执行时间 / 项数 / 节省 token 有没有出现
- 长结果后会话有没有断

### 你发给我什么

- 你用了哪条指令
- 触发的是哪类长结果
- 微压缩摘要有没有更新
- 压缩后会话有没有丢关键上下文

### 通过标准

- 长输出下能看到微压缩摘要变化
- 摘要里能看出执行痕迹
- 不把会话压断

## 7. 场景 3：memory / polluted / forgetting / phase2

### 发给 ArkPilot 的指令

#### 3.1 触发外部信息污染

```text
请联网搜索“Anthropic prompt caching latest documentation”，打开一个结果并总结重点，再继续保留这些信息用于后续任务。
```

如果你本地更容易触发 MCP，也可以换成：

```text
请调用一个 MCP 工具获取一段外部信息，并基于结果给我总结。
```

#### 3.2 继续同一线程

```text
继续基于刚才搜到的外部信息，整理成 3 条结论，不要重新搜索。
```

#### 3.3 再推进一轮

```text
继续当前线程，把刚才的结论和当前本地代码上下文结合起来，再给我下一步建议。
```

### 你看什么

- memoryMode 是否变化
- polluted / forgetting 文案是否出现
- phase2 / summary / usage / stage1 job 是否能跟着变

### 你发给我什么

- 你用了哪条指令
- memory 模式现在是什么
- 有没有 polluted / forgetting
- phase2 / summary / usage / stage1 job 哪些变了

### 通过标准

- memory 状态能看懂
- polluted / forgetting 有可见变化
- phase2 / summary / usage / job 不乱跳、不串线程

## 8. 场景 4：完整压缩与战后重建

### 发给 ArkPilot 的指令

在一个已经比较长的线程里，连续发下面几句：

```text
继续刚才的任务，保持当前线程上下文连贯，不要重新总结已有内容。
```

```text
继续往下做，并尽量引用当前线程前面已经出现过的结论和文件线索。
```

```text
如果上下文已经很长，就继续基于现有线程内容推进，不要换题。
```

如果你看到疑似已经发生完整压缩，再发：

```text
压缩后继续刚才的问题，直接延续上一个结论，不要重新开始。
```

### 你看什么

- 完整压缩 notice 有没有出现
- trigger / provider / trimmed / reestablished 有没有变化
- recent artifact refs 有没有保留
- 压缩后还能不能继续聊同一件事

### 你发给我什么

- 你连续发了哪些句子
- 这次像是手动还是自动触发
- notice 里有没有 trigger / provider / trimmed / 重建
- 压缩后还能不能继续原话题

### 通过标准

- 压缩后仍能继续当前工作
- notice 能解释清楚结果
- 不出现明显失忆

## 9. 场景 5：auto-compact / failure / circuit breaker

### 发给 ArkPilot 的指令

在长线程里连续发这些短句，让它持续工作：

```text
继续。
```

```text
再往下推进，不要换话题。
```

```text
保持当前线程继续处理，不要重开思路。
```

```text
继续刚才的任务，直接接着做。
```

如果它出现报错、自动压缩或异常，再补一句：

```text
继续当前线程，不要重置上下文，也不要换目标。
```

### 你看什么

- failure count 有没有涨
- circuit breaker 有没有打开
- 是否出现“已熔断 / 等待手动重试”这类提示
- 有没有重复自动兜底

### 你发给我什么

- 你连续发了哪几句
- failure count / circuit 有没有变化
- 有没有重复触发
- 提示文案是不是清楚

### 通过标准

- 失败后能看到熔断痕迹
- 不重复兜底
- UI 能解释当前状态

### 不要求

- cooldown 剩余时间
- skip reason
- 统一 skip reason 事实源

## 10. 场景 6：重启恢复与回归

### 发给 ArkPilot 的指令

先确保前面至少已经跑出两类状态，然后重启应用，回到同一线程后发：

```text
继续刚才的任务，如果你还保留当前线程的重要上下文，就直接基于原来的线索继续。
```

再补一句：

```text
请不要重新开始，只延续刚才这个线程已经形成的结论。
```

### 你看什么

- 摘要是否恢复
- 线程内容是否还能继续
- 是否重置、串线程、消失

### 你发给我什么

- 重启前你已经触发了哪些状态
- 重启后哪些还在
- 哪些丢了、哪些恢复正常

### 通过标准

- 主要摘要能恢复
- 继续对话不异常
- 不把别的线程恢复到当前线程

## 12. 验收结论

### 12.1 已执行场景结果

#### 场景 1：基础展示与线程恢复
- 结果：未通过
- 实际现象：
  - 切线程后 `contextManagement` 不会立即跟着变
  - 重启应用后不能直接恢复
  - 发送一句新消息后状态才恢复
- 结论：
  - 当前更像“下一轮 turn 才刷新”的懒恢复，不满足“切线程即刷新、重启即恢复”的验收目标

#### 场景 2：微压缩
- 结果：通过
- 实际现象：
  - 微压缩相关链路没有发现异常
- 结论：
  - 当前微压缩主链表现正常，可视为通过

#### 场景 3：memory / polluted / forgetting / phase2
- 结果：待复查
- 实际现象：
  - 当前无法明确判断这些状态的含义与预期行为
- 结论：
  - 需要补一次“术语含义与预期 UI 表现”的对照后再复验；现阶段不能判通过

#### 场景 4：完整压缩与战后重建
- 结果：通过
- 实际现象：
  - 完整压缩链路没有发现异常
- 结论：
  - 当前完整压缩与压缩后继续对话表现正常，可视为通过

#### 场景 5：auto-compact / failure / circuit breaker
- 结果：不在本轮范围
- 实际现象：
  - 当前 auto-compact 未作为可验证完成项落地
- 结论：
  - 本轮不把 auto-compact 作为通过条件，记入待后续

#### 场景 6：重启恢复与回归
- 结果：待复查
- 实际现象：
  - 已观察到“重启后不能直接恢复、发一句话后恢复”的问题，但还未独立完成完整回归记录
- 结论：
  - 该场景与场景 1 的恢复问题相关，待修复后统一复验

### 12.2 通过项
- 微压缩主链通过
- 完整压缩与战后重建主链通过

### 12.3 未通过项
- 线程切换后 `contextManagement` 不能立即刷新
- 应用重启后 `contextManagement` 不能直接恢复，需发送一条新消息后才恢复

### 12.4 待复查项
- `memory / polluted / forgetting / phase2` 的实际触发路径、UI 文案可理解性与验收口径
- 重启恢复与基础回归场景，在修复线程切换 / 冷启动恢复问题后需要再验一次

### 12.5 明确不验收 / 待后续
- auto-compact cooldown / skip reason
- memory 编辑器
- artifact 诊断页
- 独立 context 设置页

### 12.6 后续动作
- 修复线程切换时 `contextManagement` 未即时切换的问题
- 修复应用重启后 `contextManagement` 不能直接恢复的问题
- 给 `memory / polluted / forgetting / phase2` 补一份“术语含义 → 预期 UI 现象”的对照，再复验场景 3
- 在上述问题处理后，重新执行场景 1、场景 3、场景 6
