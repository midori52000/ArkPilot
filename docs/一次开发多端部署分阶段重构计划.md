## 阶段 1：建立全局断点能力

### 目标
为项目建立统一的响应式基础设施，让所有页面都能根据窗口宽度切换布局。

### 要做的工作

1. 新增断点类型文件。

   建议新增：

   ```text
   entry/src/main/ets/adaptive/BreakpointTypes.ets
   ```

   定义统一断点：

   ```ts
   export type ArkPilotBreakpoint = 'xs' | 'sm' | 'md' | 'lg'
   ```

2. 新增断点监听管理器。

   建议新增：

   ```text
   entry/src/main/ets/adaptive/BreakpointManager.ets
   ```

   断点规则：

   | 断点 | 范围 | 目标布局 |
   |---|---:|---|
   | `xs` | `< 320vp` | 极窄单栏 |
   | `sm` | `320vp - 600vp` | 手机单栏 |
   | `md` | `600vp - 840vp` | 平板 / 折叠屏双栏 |
   | `lg` | `>= 840vp` | 大屏 / 2in1 三栏 |

3. 使用 `@ohos.mediaquery` 监听窗口宽度。

   断点变化时写入：

   ```ts
   AppStorage.setOrCreate('arkPilotBreakpoint', breakpoint)
   ```

4. 在应用启动链路初始化断点监听。

   推荐位置：

   - `entryability/EntryAbility.ets`，如果适合全局初始化；或
   - `pages/Index.ets` 首次 `aboutToAppear`，但要避免重复初始化。

5. 新增布局配置工具。

   建议新增：

   ```text
   entry/src/main/ets/adaptive/LayoutProfiles.ets
   ```

   用来集中管理：

   - 当前布局模式：phone / tablet / desktop。
   - 左侧面板是否常驻。
   - 右侧工具面板是否常驻。
   - 默认左右面板宽度。
   - 弹窗默认宽度。

### 验收标准

- 任意页面可以通过以下方式读取当前断点：

  ```ts
  @StorageProp('arkPilotBreakpoint')
  currentBreakpoint: ArkPilotBreakpoint = 'sm'
  ```

- 改变窗口宽度、平板分屏、折叠屏展开 / 折叠时，断点能动态变化。
- 项目内只有一套断点定义，避免每个页面各写一套尺寸规则。

## 阶段 2：重构主工作台 `Index.ets`

### 目标
让 ArkPilot 主 Chat 工作台真正支持手机单栏、平板双栏、大屏三栏。

### 要做的工作

1. 保留现有业务状态，不先大规模拆业务逻辑。

   暂时继续保留在 `Index.ets` 中的状态：

   - 会话列表。
   - 当前工作区。
   - Chat 消息。
   - 输入草稿。
   - diff 状态。
   - token 用量。
   - 审批请求。
   - MCP / Provider / collaboration mode 状态。

2. 先在 `Index.ets` 内抽出三个布局 Builder。

   建议先做同文件内拆分：

   ```ts
   @Builder
   private phoneWorkspace() {}

   @Builder
   private tabletWorkspace() {}

   @Builder
   private desktopWorkspace() {}
   ```

   不要第一步就拆成多个文件，避免状态透传过多导致风险扩大。

3. 修改 `build()`，根据断点选择布局。

   逻辑：

   ```ts
   if (this.currentBreakpoint === 'lg') {
     this.desktopWorkspace()
   } else if (this.currentBreakpoint === 'md') {
     this.tabletWorkspace()
   } else {
     this.phoneWorkspace()
   }
   ```

4. 桌面布局 `desktopWorkspace()` 复用当前三栏布局。

   当前 `Index.ets` 文件末尾的结构：

   ```text
   Row
     ├─ leftPanel()
     ├─ centerPanel()
     └─ rightPanel()
   ```

   迁移为桌面布局，保留：

   - `showLeftDrawer`
   - `showRightDrawer`
   - `leftPanelWidth`
   - `rightPanelWidth`
   - 左右拖拽分隔条
   - 左右面板隐藏 / 恢复逻辑

5. 新增平板布局 `tabletWorkspace()`。

   平板布局建议：

   ```text
   Row
     ├─ leftPanel：项目 / 会话列表
     └─ centerPanel：Chat 主区域
   ```

   要做的调整：

   - 左侧面板常驻，但宽度固定在 260-300vp。
   - 默认不常驻右侧 `rightPanel()`。
   - diff、token、approval 改成临时详情面板或浮层。
   - 如果出现审批请求，优先展示审批面板。

6. 新增手机布局 `phoneWorkspace()`。

   手机布局建议：

   ```text
   Column
     ├─ mobileTopBar
     ├─ Chat 消息区域
     └─ Composer 输入区
   ```

   要做的调整：

   - 默认只显示 Chat 主流程。
   - 项目 / 会话列表通过抽屉、全屏页或弹层打开。
   - diff 通过全屏详情打开。
   - token 用量折叠成轻量状态卡。
   - 审批请求使用底部 Sheet 或全屏确认页，不能隐藏在右侧栏。
   - 输入区按钮在窄屏下折叠为更多菜单。

7. 处理右侧工具面板在不同断点下的展示方式。

   | 功能 | 手机 | 平板 | 大屏 |
   |---|---|---|---|
   | Approval | 底部 Sheet / 全屏 | 浮层 / 临时右栏 | 右栏常驻 |
   | Diff | 全屏详情 | 临时详情区 | 右栏常驻 |
   | Token | 折叠状态卡 | 折叠卡片 | 右栏常驻 |
   | Runtime status | TopBar 简化展示 | 顶部 / 侧边状态 | 右栏 / 顶部完整展示 |

8. 检查 Chat 消息区滚动。

   要保证：

   - 切换断点后消息不丢失。
   - 发送消息后仍能滚动到底部。
   - 手机输入法弹起时不遮挡 Composer。

9. 检查审批主流程。

   要保证：

   - 有审批请求时，手机、平板、大屏都能明显看到。
   - 用户可以完成 approve / deny。
   - 审批弹层不阻断消息滚动和输入状态恢复。

### 验收标准

- 手机宽度下，主页面只保留 Chat 主流程，不再强行显示三栏。
- 平板宽度下，会话列表和 Chat 并排显示。
- 大屏宽度下，当前三栏工作台体验不退化。
- 审批、diff、token 在三种布局下都有明确入口。
- 切换窗口宽度不会丢失当前会话、输入草稿和选中工作区。

## 阶段 3：重构设置页 `SettingsPage.ets`

### 目标
让设置页支持手机顶部 tab、平板 / 大屏侧边导航。

### 要做的工作

1. 抽出设置导航组件。

   建议新增：

   ```text
   entry/src/main/ets/components/settings/SettingsNavigation.ets
   ```

   支持两种模式：

   - `topTabs`：手机使用。
   - `sidebar`：平板和大屏使用。

2. 在 `SettingsPage.ets` 中根据断点选择布局。

   手机：

   ```text
   Column
     ├─ topBar()
     ├─ SettingsNavigation(topTabs)
     └─ contentArea()
   ```

   平板 / 大屏：

   ```text
   Column
     ├─ topBar()
     └─ Row
         ├─ SettingsNavigation(sidebar)
         └─ contentArea()
   ```

3. 拆分四个设置内容面板。

   建议逐步拆出：

   ```text
   components/settings/ApiSettingsPanel.ets
   components/settings/SkillsSettingsPanel.ets
   components/settings/PromptsSettingsPanel.ets
   components/settings/McpSettingsPanel.ets
   ```

   第一轮可以只抽 UI Builder，不必立即迁移所有状态。

4. 处理固定宽度弹窗。

   当前设置页中存在多个固定宽度：

   - 360vp
   - 420vp
   - 460vp

   需要改成按断点选择：

   | 断点 | 弹窗策略 |
   |---|---|
   | `xs/sm` | 接近全宽，左右保留 16vp 边距，必要时改全屏 |
   | `md` | 360-420vp |
   | `lg` | 420-520vp |

5. 处理表单布局。

   手机：

   - 表单项单列纵向排列。
   - 按钮满宽或双按钮并排。
   - JSON / 长文本输入默认折叠或降低高度。

   平板 / 大屏：

   - 表单可以双列。
   - 列表和详情可以并排。
   - 操作按钮可以放在右上角或卡片底部。

6. 分别验证四个 tab。

   - API：Provider 添加、编辑、验证、测速。
   - Skills：已安装、仓库源、备份。
   - Prompts：列表、编辑、保存。
   - MCP：Server 添加、删除、配置、JSON 导入。

### 验收标准

- 手机宽度下，设置页不出现横向挤压。
- 手机下不显示固定左侧 sidebar。
- 平板和大屏下保留侧边导航效率。
- 所有设置弹窗在手机下可完整操作。
- API、Skills、Prompts、MCP 四个 tab 的核心操作都可用。

## 阶段 4：重构管理类页面和卡片列表

让 API、Prompt、Skill、MCP 等管理类页面使用响应式列表 / 表单 / 详情结构。

### 要做的工作

1. Provider 管理响应式改造。

   页面涉及：

   ```text
   pages/ApiManagementPage.ets
   pages/AddProviderPage.ets
   ```

   要做：

   - Provider 卡片列表使用 `GridRow/GridCol`。
   - 手机下一列。
   - 平板下两列。
   - 大屏下三列。
   - 添加 / 编辑 Provider 表单在手机下独立页面或全屏 Sheet，大屏下可以作为右侧编辑面板。

2. Prompts 管理响应式改造。

   页面涉及：

   ```text
   pages/PromptsPage.ets
   ```

   要做：

   - 手机：Prompt 列表 -> Prompt 编辑页。
   - 平板：左侧列表 + 右侧编辑。
   - 大屏：列表 + 编辑 + 预览 / 元信息。

3. Skills 管理响应式改造。

   要做：

   - 已安装 Skills 使用响应式卡片。
   - 仓库源和备份使用响应式列表。
   - Skill 详情手机全屏，大屏弹窗。
   - ZIP 导入等后续功能预留响应式入口。

4. MCP 管理响应式改造。

   要做：

   - 手机：Server 列表 -> Server 配置。
   - 平板 / 大屏：Server 列表 + 配置表单双栏。
   - JSON 粘贴配置区域在手机下默认折叠。

5. 抽公共响应式组件。

   建议新增：

   ```text
   components/common/ResponsiveDialogContainer.ets
   components/common/ResponsiveFormSection.ets
   components/common/ResponsiveCardGrid.ets
   ```

   用来减少各页面重复写断点判断。

### 验收标准

- Provider / Prompt / Skill / MCP 的列表在不同断点下列数合理。
- 手机下管理流程不依赖大屏侧栏。
- 平板 / 大屏下能利用横向空间提升效率。
- 固定宽度卡片和表单基本消除。

## 阶段 5：多端交互细节补齐

### 目标
补齐手机、平板、2in1/PC 的交互差异，让多端体验不是简单拉伸。

### 要做的工作

1. 手机交互优化。

   - 顶部栏只保留核心状态和入口。
   - 次要操作进入更多菜单。
   - 输入区按钮换行或折叠。
   - 审批、选择、确认类交互使用 Sheet / 全屏页。

2. 平板交互优化。

   - 保持左侧会话常驻。
   - 右侧详情按需出现。
   - 横竖屏切换时保持选中状态。

3. 2in1 / PC 交互优化。

   - 保留拖拽面板宽度。
   - 支持 hover 态。
   - 检查鼠标点击热区。
   - 后续可增加键盘快捷键。

4. 折叠屏和分屏优化。

   - 窗口宽度变化时不重置会话。
   - 从 `sm` 切到 `md/lg` 后，抽屉状态应合理收起。
   - 从 `lg` 切到 `sm` 后，右侧面板内容应转移到可访问入口。

5. 字体和主题适配。

   - 检查系统字体放大。
   - 检查深色模式。
   - 检查长文本、代码块、diff 行在小屏下的换行和横向滚动。

### 验收标准

- 手机主流程不拥挤。
- 平板双栏状态稳定。
- 2in1 / PC 大屏工作台效率不降低。
- 断点变化后业务状态不丢失。
- 字体放大和深色模式下没有严重布局破坏。

## 推荐实施顺序

1. 先做阶段 1：全局断点能力。
2. 再做阶段 2：`Index.ets` 主工作台布局分流。

## 最小可交付版本

如果先做一个 MVP，建议只包含：

1. `arkPilotBreakpoint` 全局断点。
2. `Index.ets` 支持：
   - 手机单栏 Chat。
   - 平板左会话 + Chat。
   - 大屏现有三栏。
3. `SettingsPage.ets` 支持：
   - 手机顶部 tab。
   - 平板 / 大屏侧边导航。
4. 手机下弹窗不溢出。

完成 MVP 后，ArkPilot 就可以从“配置上支持 phone/tablet/2in1”推进到“核心体验上符合一次开发、多端部署”。
